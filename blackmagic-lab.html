01 // OBJECTIVE & SCOPE

Evaluate controls in context.

Environment

Damn Vulnerable Web Application (DVWA), an intentionally vulnerable training application, with an edge filtering layer in the saved test environment.

Question

Which tests were blocked, which reached the application, and which responses supported an actual security impact?

BlackMagic’s contribution

The saved workspace contains command history, assessment state, operator checkpoints, structured finding records, screenshots and generated HTML reports.

What the record demonstrates

Continuity between testing and reporting, review of conflicting evidence, and separation of request acceptance from demonstrated exploitation.

03 // OBSERVATIONS & LIMITS

A response code is one signal.

CONFLICTING EVIDENCE

Query-input testing

Saved manual observations describe application record retrieval. An automated verifier separately marked a query-input test as a false positive because it detected no error, boolean difference or timing signal.

Conclusion: The disagreement needs evidence review. A verifier verdict alone cannot resolve it, and the saved observations do not establish that the tests were identical.

IMPACT NOT DEMONSTRATED IN LATER RETEST

Command-execution testing

Some earlier replay notes recorded accepted requests. A later retest recorded no command-execution output and noted application-side input validation.

Conclusion: An accepted request does not demonstrate command execution. Findings must reflect the observed application behaviour and retest context.

NO EXECUTION OBSERVED

Cross-site scripting retests

Saved retest notes describe edge blocks and non-executing DOM cases. The execution instrumentation recorded no triggered execution in the documented test set.

Conclusion: Report the tested cases and controls observed. These results do not prove that every possible XSS vector is prevented.

05 // OPERATOR & DEFENDER VALUE

Preserve enough context to make a better decision.

For the operator

  • Keep automated verdicts alongside supporting observations.
  • Separate blocked tests, accepted requests and demonstrated impact.
  • Revisit earlier findings when application behaviour changes.
  • Document uncertainty and the next validation step.

For the defender

  • Review application controls alongside edge filtering.
  • Remediate the underlying input or trust-boundary failure.
  • Retest actual behaviour rather than relying on HTTP status alone.
  • Keep regression evidence tied to a defined set of test conditions.

This saved run demonstrates checkpointing and evidence review. It does not establish end-to-end enforcement of human approval gates or a completed remediation programme.
